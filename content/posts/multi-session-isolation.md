## 事情是怎么发生的

那天我同时开着 8 个 Claude Code 会话，`cwd` 全是同一个仓库目录。
一个在改网关，一个在查线上一个推送不到的 bug，一个在写迁移，剩下的在跑各种核对。

其中一个会话干完活，工作区不干净，它很规矩地 `git stash`，切分支，办完事，`git stash pop`。

弹出来的不是它自己存的那份。

**`git stash` 的栈是整个仓库共享的，不区分是谁压进去的。**
另一个会话十分钟前压进去的半成品被当成栈顶弹了出来，和当前工作区混在一起，然后被 `pop` 消费掉——
stash 条目已经删了。那份 WIP 没了。

这不是 AI 的错。换成两个人开两个终端，结果一模一样。只是人不会一小时内开八个终端。

## 共享一个工作区，等于共享三样东西

同目录下的多个会话，共用的是：

| 共享的东西 | 谁碰了会怎样 |
|---|---|
| **一个 HEAD** | 任何人 `git checkout` / `switch`，其余所有会话正在编译的代码当场被换掉 |
| **一个 stash 栈** | `pop` 会吃掉别人的 WIP，且不可恢复 |
| **一份工作区文件** | 一次全仓格式化重排 131 个文件，所有人的 diff 全脏，谁也说不清哪行是自己改的 |

这三件事的共同点：**没有任何工具会拦你**。git 不知道有八个会话，
`make fmt` 更不知道。事故发生的时候一切命令都返回 0。

我最初的反应是加规矩：「切分支前先喊一声」「别跑全仓格式化」。
喊话这件事在会话之间根本不成立——它们不看对方的终端。规矩靠自觉，自觉靠记得，记得靠运气。

## 换个方向：把协调问题降级成隔离问题

后来我把整件事重写成一句话：

> **能隔离就别协调。大部分冲突不该靠协商解决，该靠不共享解决。**

`git worktree` 就是干这个的——同一个 `.git`，多份独立的工作区和 HEAD。
开一棵树的成本几秒钟，而上面那三类事故里的**前两类直接归零**：
各自的 HEAD、各自的 stash 栈。

Claude Code 启动时带一个参数就够：

```bash
claude -w my-feature      # 直接在独立 worktree 里开会话
```

会话跑到一半才发现要写文件的，中途也能切进去。

这一步做完，剩下真正跨不过去的共享只有三类，数量少到可以逐个管：

1. **远端分支**——两个会话推同一条分支
2. **测试环境 / 测试库**——同一份数据被两边改
3. **有状态的外部资源**——比如一个全局的分发锁

这三类才值得上锁、上协议。而它们只有原来问题的三分之一不到。

## 但「我该不该隔离」这个判断也不能靠记性

隔离的前提是知道现在有几个会话在同一个目录里。这件事**不能凭印象**——
我印象里永远是「就两三个吧」，实际 `ps` 出来是八个，其中两个是昨天崩掉没清理的残骸。

所以我写了个小工具 `mcc`，第一条命令就是 doctor：

```
$ mcc doctor
⚠️  同 cwd 活动会话: 8    ← 危险
    残留 worktree: 4 (其中 3 个 prunable)
    未提交改动: 12 files
    stash 栈深度: 3        ← 有别人的东西，不要 pop
```

有了这行输出，判据就变成可执行的了：

> **同 cwd 活会话 > 1，且这次要写文件 → 先隔离。**

不是「感觉人多的时候注意一下」。是一条能跑出来的命令加一个不含形容词的阈值。

## 顺带一个反直觉的细节：别用 shell 函数包工具

我最早把 `mcc` 写成一个 shell 函数，想着方便。结果每次调用都失败——

**AI 编码工具的 Bash 调用之间，shell state 不存活。**
每次 `Bash(...)` 是一个新 shell：环境变量没了、函数定义没了、`cd` 也不留。
函数每次都得重新定义一遍，等于没有。

改成一个 symlink 就一劳永逸：

```bash
ln -sf ~/.claude/skills/cli-collab/scripts/mcc ~/.local/bin/mcc
```

这条对所有给 AI 用的工具都成立：**要么是磁盘上真实存在的可执行文件，
要么每次调用都自带完整上下文。别指望上一次调用留下的任何东西。**

## 最后：四层，越靠前越便宜

整套东西现在是一个 Claude Code Skill，按成本从低到高排四层：

- **L0 隔离**——能不共享就不协调（worktree）。解决八成问题。
- **L1 抢占**——真共享不了的（远端分支、测试库），加锁，写清楚锁键、TTL、抢不到时是等还是跳过。
- **L2 对话**——会话之间点名发消息。只有在一方必须等另一方结果时才用。
- **L3 交接**——上下文满了要换会话接着干，把状态落到文件而不是口述。

排序本身就是主张：**每往下一层，成本翻倍、可靠性下降。**
所以正确的问法不是「怎么协调这八个会话」，而是「这八个里有几个其实不需要协调」。

答案通常是七个。
