## 问题

把工单系统接进日常开发：拉自己名下的单、读需求规格、按单号进入实现或排障、提交合并请求、从工单生成日报周报。

难点不在调 API，在**怎么让这个能力不绑死在某一个 agent 上**。

## 设计理念

### 一 · 能力做成 CLI，skill 只是使用说明

所有实际动作都由一个薄 CLI 完成，skill 负责讲清什么时候用哪条命令。这样任何能跑 shell、能改代码的 agent 都能用——**skill 是 agent-agnostic 的，绑定发生在 CLI 那一层。**

### 二 · 纯标准库，零依赖

没有第三方 HTTP 库、没有 venv、不需要安装。把整个文件夹复制给同事就能用，他只需要补自己的凭证。

一个需要 `pip install` 才能跑的内部工具，实际扩散率接近零。

### 三 · 每次开工先跑 check

打印当前配置与凭证状态。就绪才往下走——和其他几个 skill 同一条原则：**先验环境，再干活。**

### 四 · 报告类产出有严格模板

日报、周报、量化进度同步各有固定骨架。模板固定之后，产出才可比较；每次现编格式，读的人要重新适应一次。

## 为什么不开源

含组织与空间标识、接口细节。CLI 本身可以脱敏，在队列里。
