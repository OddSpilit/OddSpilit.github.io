## 问题

同一台机器上常态八个 AI 编码会话，`cwd` 全指向同一个仓库。一个 HEAD、一个 stash 栈、一份工作区文件。

这三件事任何一个会话做了，其余七个的活当场报废：

| 动作 | 后果 |
|---|---|
| `git checkout` / `switch` | 别人正在编译的代码被换掉 |
| `git stash pop` | stash 栈**全仓共享**，pop 会吃掉别人的 WIP，且 stash 条目已删、不可恢复 |
| 全仓格式化 | 一次重排 131 个文件，所有人的 diff 全脏 |

共同点：**没有任何工具会拦你**。git 不知道有八个会话，事故发生时所有命令都返回 0。

## 设计理念

### 一 · 把协调问题降级成隔离问题

最初的反应是加规矩——「切分支前先喊一声」。喊话在会话之间根本不成立，它们不看对方的终端。规矩靠自觉，自觉靠记得，记得靠运气。

换个方向：**能隔离就别协调。大部分冲突不该靠协商解决，该靠不共享解决。**

`git worktree` 一棵树几秒钟，上面三类事故的前两类直接归零——各自的 HEAD、各自的 stash 栈。剩下真正跨不过去的共享只有三类：远端分支、测试库、有状态的外部资源。数量少到可以逐个上锁。

### 二 · 判据不能是形容词

「人多的时候注意一下」不是判据。印象里永远是「就两三个吧」，`ps` 出来是八个，其中两个是昨天崩掉的残骸。

所以第一条命令是 `doctor`：现跑一遍，打印同 cwd 活会话数、残留 worktree 数、stash 栈深度。判据变成——**同 cwd 活会话 > 1 且这次要写文件 → 先隔离**。一条能跑的命令加一个不含形容词的阈值。

### 三 · 四层，越靠前越便宜

L0 隔离（worktree）→ L1 抢占（锁，写清锁键/TTL/抢不到时是等还是跳过）→ L2 对话（点名发消息）→ L3 交接（状态落文件，不口述）。

排序本身就是主张：**每往下一层成本翻倍、可靠性下降**。所以正确的问法不是「怎么协调这八个会话」，而是「这八个里有几个其实不需要协调」。答案通常是七个。

## 一个反直觉的细节

最早把工具写成 shell 函数，每次调用都失败——**AI 工具的 Bash 调用之间 shell state 不存活**。每次是一个新 shell：环境变量、函数定义、`cd` 全没了。

改成磁盘上的 symlink 就一劳永逸。这条对所有给 AI 用的工具都成立：**要么是真实存在的可执行文件，要么每次调用自带完整上下文。别指望上一次调用留下任何东西。**

## 它挡不住什么

挡不住两个会话在**不同 worktree** 里改同一个文件后各自提交——那是 merge 该解决的问题，隔离只保证你不会丢没提交的东西。也挡不住人绕过工具直接手敲 `git stash pop`。
